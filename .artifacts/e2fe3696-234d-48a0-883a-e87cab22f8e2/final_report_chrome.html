1. Database Management (The Storage Engine)

This section covers the core database infrastructure used to store student data permanently.

DatabaseHelper.java

Component TypeName / IdentifierPurpose in Project
ConstantDATABASE_NAMEDefines the physical database filename: "StudentReminder.db".
ConstantTABLE_SCHEDULE, TABLE_SUBJECT, TABLE_REVIEW, TABLE_TODOUnique names for the tables used to organize different data entities.
ConstantCOL_ID, COL_SUBJECT, COL_DAY, etc.Standardized column names for the SQL tables to ensure data consistency.
MethodonCreate()Automatically runs when the app starts for the first time to build the table structure.
MethodinsertSubject() / insertReview()Takes validated data from the UI and writes a new row into the database.
MethodgetAllSubjects() / getSchedulesByDay()Queries the database to retrieve lists of information for the student to view.
MethodupdateTodoCompleted()Handles the logic for marking a checklist task as "Done" in the database.
MethoddeleteReview() / deleteSchedule()Allows the user to remove specific records by their Unique ID.

2. User Interface Controllers (Activities)

These classes manage the screens, inputs, and the lifecycle of each application view.

AddReviewActivity.java

Variable / MethodPurpose / Description
etSubject, etTopic, etDate, etTimeInput fields used by the student to enter specific study session details.
dropdownReminderA dropdown menu for selecting when to be notified (e.g., 10 minutes before).
editModeA boolean flag to determine if the activity is adding a new review or editing an old one.
saveOrUpdateReview()Validates that inputs are not empty and calls the DatabaseHelper to save data.
showDatePicker() / showTimePicker()Triggers the Android system pop-ups for date and time selection.

ReviewDetailsActivity.java

Variable / MethodPurpose / Description
recyclerTodosThe vertical list container that displays the checklist for a review session.
todoAdapterThe bridge between the list of tasks and the UI layout.
showAddTodoDialog()Opens a pop-up window where the student can type a new task for the review.
loadTodos()Refreshes the task list by pulling data from the database for a specific review ID.

3. Data Models (The Blueprints)

POJO (Plain Old Java Objects) used to structure information within the app's code.

Subject, Schedule, Review, and Todo Classes

Class NameKey VariablesFunctionality
Subjectid, subject, teacher, room, colorStores data for a course, including the instructor and location.
Scheduleid, subject, day, startTime, endTimeRepresents a specific occurrence of a class in the timetable.
Reviewid, topic, date, time, reminderStores planning details for a study or exam review session.
Todoid, reviewId, task, completedRepresents a single task item with a checkbox status.

4. UI Adapters (Bridge Logic)

Adapters handle the complex logic of binding database objects to the visual list items.

SubjectAdapter, ReviewAdapter, and TodoAdapter

Method NameRole in Application
onCreateViewHolder()Inflates the XML design for a single row or card in a list.
onBindViewHolder()The most active method; it sets text, colors, and click listeners for each list item.
updateTaskStyle()(TodoAdapter) Logic that changes the font to strikethrough when a task is finished.
