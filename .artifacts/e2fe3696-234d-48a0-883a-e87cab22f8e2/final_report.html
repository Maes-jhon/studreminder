StudReminder: Project Components Report

Group Activity Submission

1. DATABASE MANAGEMENT (DatabaseHelper.java)

Constants (Global Settings)

  • DATABASE_NAME: The filename for the SQLite database ("StudentReminder.db").
  • TABLE_SUBJECT, TABLE_REVIEW, TABLE_TODO: The names of the internal storage tables.
  • COL_ID, COL_SUBJECT, COL_ROOM: Names of the columns used to organize data in rows.

Methods (Functions)

  • onCreate(): Runs when the app is first installed to build the database structure.
  • insertSubject() / insertReview(): Saves new user information into the database.
  • getAllSubjects() / getAllSchedules(): Fetches all saved data to show on the screen.
  • updateTodoCompleted(): Changes a task status from "Pending" to "Done".
  • deleteSubject() / deleteSchedule(): Removes a specific item from the database.

2. USER INTERFACE CONTROLLERS (ACTIVITIES)

AddReviewActivity.java

Variables: etSubject, etTopic, etDate, dropdownReminder, databaseHelper.

Methods:

  • saveOrUpdateReview(): Validates user input and calls the database to save the review.
  • showDatePicker(): Displays a calendar popup for the user to select a date.

SubjectsActivity.java

Variables: recyclerSubjects, adapter, subjectList.

Methods:

  • loadSubjects(): Refreshes the list by pulling the latest data from the DatabaseHelper.

3. DATA MODELS (BLUEPRINTS)

Subject.java, Review.java, Todo.java: These classes define the properties of each item.

  • Variables: id, subjectName, teacherName, roomNumber, isCompleted.
  • Purpose: They allow the app to treat data as "Objects" that can be easily passed between screens.

4. UI ADAPTERS (LIST LOGIC)

SubjectAdapter.java, ReviewAdapter.java, TodoAdapter.java:

  • onBindViewHolder(): The core method that maps database data to the visual elements (TextViews) on the phone screen.
  • getItemCount(): Tells the app how many items are in the list so it knows how much to scroll.
