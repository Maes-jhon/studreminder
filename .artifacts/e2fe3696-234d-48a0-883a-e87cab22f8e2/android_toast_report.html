ANDROID TOAST DOCUMENTATION

1. Where Android Toast is Applied in the Project

Android Toast is currently applied in the Subject and Schedule modules of the StudReminder application. It is used to give the user immediate, non-intrusive feedback about the result of an action — specifically, whether their attempt to add a subject or save a schedule succeeded or failed — without interrupting their workflow or requiring them to dismiss a dialog box.

Purpose of the Toast Applied

  • In the AddSubjectActivity, Toast is used to inform the user whether their entered subject details were successfully saved. This gives immediate confirmation of success ("Subject Added") or a clear indication of failure ("Failed") so the user knows the status of their data entry.
  • In AddSubjectActivity and AddScheduleActivity, Toast is also used for input validation — for example, alerting the user when a required field like the subject name, teacher, or room is left empty.
  • In ReviewAdapter, Toast confirms the successful deletion of a review session, guiding the user that the record has been removed from the list.
  • Overall, Toast messages were chosen because they are lightweight, appear briefly on screen, and do not require the user to tap anything to dismiss them — making them ideal for quick status updates like successful data entry or validation results.

2. Explanation of the Toast Code

Example 1 — Successful Subject Entry

Toast.makeText(this, "Subject Added", Toast.LENGTH_SHORT).show();

Explanation:

  • Toast.makeText(...) creates a new Toast object with three arguments.
  • this refers to the current context (AddSubjectActivity), which tells Android which screen/application the Toast belongs to.
  • "Subject Added" is the message string that will be displayed to the user.
  • Toast.LENGTH_SHORT sets how long the message stays visible on screen (a brief duration, roughly 2 seconds).
  • .show() is called at the end to actually display the Toast on screen; without this, the Toast object is created but never shown.

Example 2 — Failed Data Entry

Toast.makeText(this, "Failed", Toast.LENGTH_SHORT).show();

Explanation:

  • This follows the exact same structure as Example 1, but is placed inside the else branch of the database insertion logic — meaning it only runs when the database helper returns false (the data was not saved). This gives the user clear, immediate feedback that the operation failed.

Example 3 — Empty Field Validation

Toast.makeText(this, "Complete all fields", Toast.LENGTH_SHORT).show();

Explanation:

  • This Toast is triggered inside an if statement that checks whether the subject name, teacher, or room fields are empty before the app even attempts to save to the database. This prevents unnecessary database calls and immediately tells the user what is missing.

Example 4 — Successful Review Deletion

Toast.makeText(context, "Review Deleted", Toast.LENGTH_SHORT).show();

Explanation:

  • This Toast runs after the delete method is called in the adapter, confirming that the record was successfully removed from the SQLite database. It provides the user with visual confirmation of their deletion request.
